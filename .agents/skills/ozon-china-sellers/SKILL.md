# Китайские продавцы на Ozon

## Главное правило

**Единственный абсолютный признак китайского продавца — 18-значный USCC в блоке
реквизитов.** Всё остальное (латиница в названии, срок доставки, склад, телефон
+86) — лишь вспомогательные сигналы, и каждый из них даёт ложные срабатывания.

Если пользователь жалуется, что «парсер врёт» и показывает российских
продавцов — почти всегда причина в одном из трёх мест, проверяй именно их:

1. **Перепутанные данные из-за гонки.** Воркеры ходят по одной вкладке Chrome и
   читают чужие ответы. Признак: одна компания приписана нескольким витринам,
   в поле компании текст интерфейса («Фото и видео покупателей», «Товар
   закончился»). Чинится в `src/utils/selenium_manager.py` — своя вкладка на
   воркера.
2. **Нестрогая регулярка USCC.** Шаблон `\b[0-9A-Z]{18}\b` ловит служебные
   токены Ozon. Нужен строго `9[123]\d{6}[0-9A-Z]{10}` и только в реквизитах.
3. **Скан всего JSON.** Слова «Китай» и иероглифы встречаются в описаниях
   товаров и отзывах. Искать их можно только в названии продавца и реквизитах.

## Как подтвердить страну

### Способ 1 — USCC (абсолютный)

Модалка `GET /api/composer-api.bx/page/json/v2?url=/modal/shop-in-shop-info?seller_id=<id>&__rr=1`.
Нужен `textBlock` с `textColor: tertiary`, строки склеены через `<br>`:

```
китайский — три строки:                российский — две:
  Yiwushisenyibaozhuangzhipinyouxiangongsi   ИП Дубовик Василий Николаевич
  yiwushi                                    319703100086469   ← ОГРНИП
  91330782MAEATRWE13  ← USCC
```

Провинция выводится из кода: цифры 3-8 — код региона GB/T 2260, первые две —
провинция. Таблица `USCC_PROVINCES` в `src/parsers/chinese_filter.py`.

Функции: `extract_seller_registration(text)`, `province_from_uscc(uscc)`,
`classify_seller(..., registration_block=...)`.

### Способ 2 — склад продавца (когда реквизитов нет)

Виджет доставки: `POST /api/composer-api.bx/widget/json/v2?widgetStateId=<id>`
с телом `{"asyncData": <из layout>, "extraBody": null, "url": <путь>, "componentName": "pdp.webDelivery"}`.

Без `asyncData` — **400**. `asyncData` лежит в узле `layout` с
`"component":"webDelivery"`.

Признаки в ответе:
* секция `"type":"global_info"` → доставка из-за рубежа;
* строка `Со склада продавца, <регион>` → страна склада.

Логика в `src/crm/verify.py`, функция `verify_by_warehouse(raw)`.

## Чего делать НЕЛЬЗЯ

Проверено на живом Ozon — эти поля выглядят подходящими, но врут:

| Что | Почему нельзя |
|---|---|
| `country`, `countryCode`, `countryId` | Это страна **покупателя**, всегда `Россия`/`RUS`/`1` |
| `from_global=true` | Не фильтр: выдача с ним и без идентична |
| `selectedDeliverySchema` | Одинаковый у китайских и российских |
| числовой ID в ссылке на магазин | Встречается у обеих сторон |
| «Со склада продавца» | Так пишет и российский: «Со склада продавца, Московская» |
| латиница в названии | У турецких склад `Istanbul`, у польских `Lower Silesian` |
| `webDelivery` в карточке товара | Всегда `{}` — состояние грузится отдельным POST |

## Сбор продавцов

Раздел «Товары из Китая»: `/highlight/tovary-iz-kitaya-935133/`, пагинация
`?page=N`, 8 товаров на страницу. Товары там китайские (проверено на страницах
1, 2, 3, 50).

```bash
python run_harvest.py harvest --pages 10    # собрать в базу
python run_harvest.py list --limit 30       # посмотреть
python run_harvest.py show <seller_id>      # подробности
```

**Критичная ловушка:** на странице раздела два товарных грида. Настоящий
листинг — тот, у которого `params` строго `"{}"`. У рекомендаций в params есть
`"title":"Возможно, вам понравится"`, и в них лежат **российские** товары. В
рекомендательном гриде 30 позиций против 8, поэтому соблазн взять его велик — и
тогда получишь «китайский раздел» со складом в Ленинградской области.

Кириллицу Ozon экранирует как `\u0417...` — раскодируй строку до поиска меток.
Не используй `decode("unicode_escape")`: он съедает кириллицу.

## База и дашборд

Единая база: `data/sellers.sqlite3` (`src/crm/store.py`). Ключевое поле —
`verified_by`:

* `uscc` — подтверждён кодом (абсолютно);
* `warehouse` — подтверждён складом в Китае;
* `heuristic` — только эвристики по названию, **не доказательство**.

Дашборд и рассылка по умолчанию работают только с первыми двумя. Эвристики
хранятся, но скрыты — именно они давали ложные плюсы.

```bash
./start_dashboard.sh                # http://127.0.0.1:8000, пароль в .env
python run_harvest.py note <id> "текст"
python run_harvest.py status <id> replied
python run_harvest.py export --out sellers.csv
```

## Этика и ограничения

* Для парсинга аккаунт Ozon **не нужен** — всё отдаётся анонимно. Логин требуется
  только для отправки сообщений.
* Темп запросов сдерживай: на ~150 запросах подряд сессия начинает виснуть.
* Не расширяй обход детекции: маскировка в проекте существовала и раньше, но
  подмена отпечатков и мультиаккаунт для обхода лимитов — не наша задача.
* Подробности и история решений — в `AGENTS.md` и `docs/PROJECT_MEMORY.md`.
