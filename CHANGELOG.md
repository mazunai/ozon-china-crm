# CHANGELOG парсера Ozon

## v1.8.3 — безопасность: замок перебора пароля, Secure-cookie, закрыт порт 8000 (2026-09-26)

- /api/login: 6 неудачных попыток с одного IP — вход с этого адреса молчит 10 минут. Живой человек не заметит, брутфорс останавливается.
- Cookie сессии получает флаг Secure при заходе через HTTPS (Caddy помечает схему); на локальном http — без него, иначе браузер cookie съест.
- Порт 8000 закрыт в группе безопасности: наружу только 443 (Caddy) и 22 (SSH). Дашборд — только через https://ozon.sh-coding.ru.
- Конвенция изоляции WB-парсера: docs/ISOLATION_WB.md — раздельные базы (WB пишет в data/wb_sellers.sqlite3, не в Ozon-CRM), раздельные логи, параллельность разрешена (разные транспорты).


## v1.9.0 — Wildberries вторым воркером: одна VM, один экран, изолированные процессы (2026-09-26)

**WB-сбор запущен в работу.** Принцип тот же, что у Ozon (выдача → реквизиты → классификация «китайский?» → CRM), но воркер WB — **отдельный OS-процесс и отдельная база** `data/sellers-wb.sqlite3`: падение или блокировка WB не задевает работающий Ozon, данные маркетплейсов не смешиваются.

- **Дашборд один.** В шапке переключатель **Ozon / WB** — таблица продавцов, сводки, статусы, заметки и CSV-экспорт меняют базу целиком (`?marketplace=` на всех CRM-эндпоинтах, дефолт ozon — старые вызовы не сломаны). Рассылка и чаты остаются Ozon-only (у WB чата с продавцом нет; рассылку WB сделаем отдельно).
- **WB-воркер без браузера**: HTTP-транспорт на `curl_cffi` с TLS-отпечатком Chrome — обычный `requests` WB закрывает (проверено). Версии эндпоинтов — списками кандидатов (`src/parsers/wb/endpoints.py`): переезд API лечится добавлением строки, а не правкой логики.
- **Супервайзер воркеров** (`dashboard/workers.py`): старт/стоп кнопкой, авто-рестарт при падении (3 подряд — сдается, чтобы не жечь IP), события воркеров в общий SSE-лог с пометкой маркетплейса. Файловый протокол как у ночного сбора: pid/стейт-JSON/стоп-файл, стейт атомарный.
- **Честный сигнал блокировки**: если WB отвечает 403/челленджем, карточка воркера показывает «WB закрыл доступ — нужен прокси», это штатное состояние, а не ошибка кода. Прокси задаётся `WB_PROXY` в `.env` (пусто — с IP машины).
- Классификация переиспользует `chinese_filter` без изменений: реквизиты WB (ИНН/ОГРН/адрес) склеиваются в формат модалки Ozon, российское юрлицо перебивает «китайские» маркеры. Тесты: `test/test_wb_harvest.py` (14), `test/test_workers_runtime.py` (7).
- Тестовый запуск воркера руками: `python run_worker.py --marketplace wb --url "органайзер" --pages 1`.

**Ограничения v1 (честно):** вход — поисковым запросом (категорийные URL WB требуют shard-параметров); эндпоинт реквизитов продавца `seller-info` на 26.09 отдаёт 404 — актуальный путь нужно снять DevTools'ом с чистого IP, кандидаты уже в конфиге; с VM IP без прокси WB скорее всего потребует прокси.

## v1.5.0 — ночной сбор по кнопке, поведение как у приложения (2026-09-26)

Большой обход за ночь можно запускать **самому, кнопкой** — без расписания и автозапуска:

- Вкладка «Сбор» → блок **«Ночной сбор»**: сколько страниц за проход, до какого часа работать, пауза между проходами. Кнопка «Запустить ночной сбор» и «Остановить» (текущий проход доигрывает, новые не начинаются). Рядом видно, что уже собрано за ночь и хвост лога.
- Внутри — `tools/night_harvest.py`: идёт порциями, при сбое повторяет ту же страницу, после серии сбоев уходит на длинную паузу, прогресс хранит в `data/night_harvest_state.json` — после перезапуска продолжает с места остановки, а не с начала. Лог: `logs/night_harvest_<дата>.log`.
- Ночной, обычный сбор и рассылка не мешают друг другу: кнопки проверяют занятость браузера и отказывают с понятной причиной, если он занят.
- `run_harvest.py harvest --json` печатает машинный итог строкой `HARVEST_JSON` — по нему автосбор понимает, что раздел кончился.
- **Мобильная версия ведёт себя как приложение**: зум отключён (`user-scalable=no` + `touch-action: manipulation`), прокрутка без «резинки» (`overscroll-behavior: none`), нет подсветки тапов и выделения служебных элементов; в окне входа поле пароля 16 px — iOS не зумит при фокусе.
- Часовой пояс ВМ переведён на Europe/Moscow: «до 08:00» и дневной лимит рассылки считаются по московскому времени.
- Автозапуск по таймеру systemd сознательно не используется — сбор стартует только по кнопке.
