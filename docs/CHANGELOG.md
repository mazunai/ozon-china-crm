# Changelog

Формат: версия — дата — что изменилось. Версии соответствуют этапам работы,
не релизам пакета.

## v0.3 — 25.09.2026 — Мини-CRM и исправление ложных «китайцев»

### Исправлено (критично)

* **Гонка на общей вкладке Chrome.** Все воркеры парсера работали в одной
  активной вкладке и перезаписывали друг другу страницу — из-за этого
  российским продавцам доставались реквизиты китайских фирм, а в поле компании
  попадал текст интерфейса. Каждый воркер получил свою вкладку.
  (`src/utils/selenium_manager.py`)
* **Ложные вердикты «Китай» у российских ИП.** Классификатор искал USCC по
  всему сырому JSON нестрогой регуляркой, которая ловила служебные токены Ozon.
  Теперь USCC строго по форме кода и только в блоке реквизитов продавца;
  иероглифы и «Китай» — только в названии продавца; российская регистрация
  перебивается только настоящим USCC. (`src/parsers/chinese_filter.py`)
* **Мусор в поле компании.** `seller_parser` выбирал «лучший textBlock»
  внутренним скорингом и брал текст интерфейса. Теперь ищет блок, у которого
  последняя строка — регистрационный номер.
  (`src/parsers/seller_parser.py`)
* **Дашборд терял данные при новом прогоне** — кэш обнулялся на старте парса.
  (`dashboard/server.py`)

### Добавлено

* Единое хранилище продавцов на SQLite с миграцией старой очереди и уровнями
  достоверности `uscc` / `warehouse` / `heuristic`. (`src/crm/store.py`)
* Харвестер раздела «Товары из Китая»: страницы → товары → продавцы → реквизиты
  → база, с защитой от грида рекомендаций. (`src/crm/harvest.py`)
* Подтверждение страны по складу продавца через виджет доставки.
  (`src/crm/verify.py`)
* CLI `run_harvest.py`: `harvest`, `list`, `show`, `stats`, `note`, `status`,
  `export`.
* Вкладка «Китайские продавцы» в дашборде: USCC, провинция, метрики, оценка,
  статус, заметка, ссылка на профиль.
* Авторизация дашборда (HTTP Basic, пароль в `.env`).
* Автосохранение продавцов в базу по завершении парса.

### Изменено

* `SellerInfo` дополнен полями `shop_name`, `registration_block`, `address`,
  `uscc`, `province`, `registration_kind`.
* `SellerClassification` дополнен полями `uscc`, `province`,
  `registration_kind`.
* Шесть кейсов в `test_chinese_filter.py` переведены в `INVERTED:` —
  фиксируют, что сигналы через служебный JSON больше не дают вердикт «Китай».

### Документация

* `AGENTS.md` — инструкция для агентов: карта проекта, проверенные факты,
  ловушки, исправленные баги, список непроверенного.
* `docs/PROJECT_MEMORY.md` — хронология решений и мотивировка.

## v0.4 — 25.09.2026 — Развёртывание на VM и адаптивный транспорт

### Проверено фактически (ранее было записано как непроверенное)

Сбор с VM в Yandex Cloud работает: 8 товаров → 7 продавцов → **5 подтверждены
по USCC** за ~26 секунд. Команда `bash tools/deploy_vm.sh` разворачивает код,
зависимости и перезапускает службу.

### Исправлено

* **`fetch` не работал на VM.** С датацентрового IP главная Ozon под
  антибот-челленджем, и запросы из её контекста блокируются. Из-за этого первый
  прогон на VM вернул 0 товаров. Транспорт стал адаптивным: харвестер
  определяет челлендж по размеру страницы и маркерам и переключается на прямые
  запросы к API — этот путь на VM работает. (`src/crm/harvest.py`)
* **Своя вкладка воркера не создавалась.** `switch_to.new_window("tab")`
  возвращал `None` вместо handle, и привязка молча не работала — то есть фикс
  гонки из v0.3 не действовал. Handle теперь берётся из
  `current_window_handle`. (`src/utils/selenium_manager.py`)
* **Подключение к Chrome падало**, если предыдущий запуск оставил браузер без
  открытых страниц (`unable to discover open pages`), и скрипт молча уходил в
  откат на автоматизированный Chrome. Добавлена проверка и создание вкладки.
* **Устаревший комментарий про Camoufox.** Написано, что он проходит проверку с
  датацентрового IP — это неверно. Исправлено с пояснением, как на самом деле
  работает обход. (`src/utils/camoufox_manager.py`)

### Добавлено

* `tools/deploy_vm.sh` — развёртывание на VM: rsync, зависимости, перезапуск
  службы, проверка ответа дашборда. Не трогает `config.txt`, базу и venv.
* Проверка origin перед запросами: с чужого домена `fetch` к Ozon блокируется
  как кросс-доменный, и это выглядело как «Ozon не отвечает».
* Понятные ошибки вместо пустых ответов: харвестер пишет причину, почему
  страница не получена.

### Известные ограничения

* Глубокий обход (десятки страниц) с VM не гонялся — неизвестно, начнёт ли Ozon
  притормаживать сессию.
* У двух витрин встретился один USCC (`Rhapsody Home Shop`, `Vandefa`) — нужно
  сверить профили вручную.

## v0.5 — 25.09.2026 — Локальная база «как в облаке», VM выключена

### Изменено

* **SQLite переведена в режим WAL** с `synchronous=NORMAL` и `busy_timeout=30s`.
  Дашборд читает базу, пока харвестер пишет — в обычном режиме журнала чтение
  падало бы с «database is locked». (`src/crm/store.py`)
* VM в Yandex Cloud **остановлена** (`yc compute instance stop`), разработка
  идёт на Mac. Данные на диске VM сохранены: при следующем старте будут на месте.

### Добавлено

* `tools/backup_db.py` — резервные копии: согласованный снимок через
  `sqlite3.Connection.backup()` в `data/backups/` с ротацией (20 последних),
  выгрузка в `backups/sellers.csv`, восстановление `--restore`, офсайт-копия
  `--push` в приватный репозиторий.

### Уточнено

* **Один USCC на несколько витрин — это норма.** Ранее было записано как
  подозрение на путаницу. Подтверждено дважды: `Nanchangtuboshumaoyi`
  (`91360106MA7FP0LG42`) держит магазины `tuboshu` и `ct`; компания
  `91360111MAC3F9Y20A` — `Rhapsody Home Shop` и `Vandefa`.

### Выяснено про serverless

Cloud Functions для парсинга не подходят: нужен настоящий браузер на минуты, у
функций лимиты по времени и нет постоянного диска, а с датацентрового IP витрина
под челленджем. Serverless годится для раздачи дашборда, но не для сбора.

### Замечено

* После прогона сбора на VM оставался висеть процесс Camoufox (493 МБ), хотя
  `close()` вызывается в `finally`. На 2 ГБ памяти такая утечка при длинном
  обходе опасна — стоит разобраться до уменьшения конфигурации VM.
